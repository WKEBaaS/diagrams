api Schema

BaaS 的公開介面層。此 Schema 中的函式會透過 PostgREST 自動轉換為 API Endpoints，提供安全的權限控管與業務邏輯存取。
PostgREST Mapping 機制
PostgREST 會將 api schema 中的 SQL Functions 暴露為 RPC (Remote Procedure Call) 端點。
  • 呼叫方式：POST /api/rest/rpc/<function_name>
  • 參數傳遞：以 JSON 物件放入 POST Body 中。
  • 權限驗證：PostgREST 處理 JWT 並切換 DB Role，函式內部透過 auth.uid() 或 auth.jwt() 取得當前使用者。
get_permission_enum GET / RPC
取得系統定義的所有權限列舉值 (Permission Enums)。此函式為 Immutable，結果可被快取。
Input Parameters
None
Return Type
setof dbo.permission_enum
check_class_permission RPC
檢查當前登入使用者 (JWT Subject) 對指定 Class 是否擁有特定的權限。會自動驗證擁有者、群組與公開權限。
Input Parameters
  • p_class_id text
  • p_permission text (e.g. 'read', 'write')
Return Type
boolean
check_class_permission_by_name_path RPC
透過路徑 (Name Path) 來檢查權限。這對於前端使用路由或麵包屑導航時非常有用。
Input Parameters
  • p_name_path text
  • p_permission text
Return Type
TABLE ( class_id varchar, has boolean )
get_class_permissions RPC
取得當前使用者對指定 Class ID 的所有權限狀態。會列出所有定義的權限並標示 True/False。
Input Parameters
  • p_class_id text
Return Type
TABLE ( permission text, has boolean )
get_class_permissions_by_name_path RPC
透過路徑取得所有權限狀態。系統會自動正規化路徑 (移除結尾斜線) 並查找對應 Class ID。
Input Parameters
  • p_name_path text
Return Type
TABLE ( class_id varchar, permission text, has boolean )
check_permission_core INTERNAL
底層的核心權限檢查邏輯。通常由其他 API 呼叫，不建議前端直接使用。
Logic
1. 檢查是否為 App Admin
2. 檢查是否為 Owner
3. 檢查 Anon/Group/User 權限位元
